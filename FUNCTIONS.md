## GPU load display contracts (2026-11-26)

- `AppSettings.ShowGpuLoad` (default true): the only switch for the dashboard GPU load percentage. `MainWindow.ApplyTelemetryVisibility` controls `TxtGpuLoad` visibility, and `UpdateTelemetryUI` writes the value from `HardwareSnapshot.GpuLoad`; `double.NaN` renders `--%`. Do not add a second GPU sensor poll.
- `HardwareMonitorService.IsGpuEngineLoadSensor(string)` recognizes `D3D` and `D3D *` sensors. `ResolveGpuLoad(double? driverLoad, double? engineLoad)` returns the busiest engine load, falling back to the driver's `GPU Core` value only when no engine sensor exists. Task Manager uses the busiest engine, not `GPU Core`; do not prefer the driver value again.
- `HardwareMonitorService.ScoreGpuLoadSensor(string)` is only the fallback ranking for driver sensors, with `GPU Core` above memory/video/copy/bus. Engine sensors bypass it and are combined by maximum in `ReadGpuTelemetry`.
- GPU row layout: `TxtGpuVendor` shares the first line with `TxtGpuLabel`; `TxtGpuTemp`, `TxtGpuPower`, and `TxtGpuLoad` share the second line; `TxtGpuName` stays on the third. This keeps the 444 px dashboard within its roughly 116 px text area. Moving the vendor back to the value line overflows.
- Dashboard value tooltips: use the XAML `DynamicResource` keys `Main_CpuClockTooltip`, `Main_CpuLoadTooltip`, `Main_CpuPowerTooltip`, `Main_GpuTempTooltip`, `Main_GpuPowerTooltip`, `Main_GpuLoadTooltip`, and `Main_GpuFanTooltip`, kept in both string files. Bind them in XAML, not from `UpdateTelemetryUI`, so localization changes update them with the window.

## Sensor and power-plan watch contracts (2026-11-26)

- `SensorDropoutWatch.Observe(bool cpuReadings, bool gpuReadings, DateTime nowUtc)`: the only dropout timing rule. Returns `SensorDropoutKind.Cpu` after `MissingSeconds` (30) of missing CPU readings while the GPU reports, `SensorDropoutKind.All` when both are missing, and `None` otherwise. The gap starts on the first missing CPU sample, a CPU reading resets it, and one `RepeatWindow` (30 min) gate covers both kinds so one outage cannot double log. `Reset()` clears the open gap.
- `SensorDropoutWatch.HasCpuReadings(HardwareSnapshot?)` and `HasGpuReadings(HardwareSnapshot?)`: the only definition of a live CPU or GPU sensor poll. CPU counts `CpuTemp` or `CpuMeasuredGhz`; GPU counts `GpuTemp`, `GpuLoad`, or any listed GPU's temperature/load. The PDH `CpuGhz` and `CpuLoad` fallbacks must not count, or a failed sensor stack would look healthy. A missing GPU alone is not a dropout.
- `PowerPlanService.IsExternalDrift(PowerProfileDefinition? previous, Guid activeGuid)`: true only when the previous profile is a CryoTray scheme and the active GUID differs. `PlanDrifted` carries `PowerPlanService.PowerPlanDrift` with `PreviousName`, `NewName`, and `NewSchemeGuid`. `RestoreOriginalPowerPlan` and `CleanupForUninstall` suppress the event; do not remove those guards.
- `AppSettings.SensorDropoutLogEnabled` and `AppSettings.PowerPlanDriftNoticeEnabled` default to `true` and are the only switches. `App.OnTelemetryUpdated` records `Activity_SensorDropout`; `App.OnPowerPlanDrifted` records `Activity_PowerPlanDrift` and shows one tray note per 10 minutes. Reuse `ActivityLogService.Record` and `App.ShowTrayNotification`; do not add another store or notification path.

## Limit Watch contracts (2026-11-25)

- `LimitWatch.IsBelowNominal(HardwareSnapshot)` / `IsBelowNominal(double measuredGhz, double baseGhz, double loadPercent)`: the only below-nominal rule. Returns false when the clock or base is missing, when load is below `LoadFloorPercent` (50), or when the measured clock is at least `NominalRatio` (0.95) of base. Do not duplicate this comparison elsewhere.

## GPU power control

- `GpuPowerControlService.Instance`: lazy singleton; `State` (`GpuPowerControlState`), `RefreshAsync()`, `EnableAsync()`, `DisableAsync()`, `ApplyPercentAsync(double)`, `ResetAsync()`, `RestoreForExit()`, `Dispose()`. All normal calls are serialized by `SemaphoreSlim(1, 1)` and run through `Task.Run`; readouts still come from `HardwareMonitorService.CurrentSnapshot`, not a second poll. The service reselects the primary GPU via `SelectPrimaryGpu`, creates a backend only for that vendor, persists `GpuPowerControlEnabled`, and restores the VBIOS default on disable, exit, unhandled exception, and session ending. Startup re-applies a saved preset only when `GpuReapplyPowerLimitOnStartup` is true; otherwise it applies the native default once.
- `GpuPowerMath.NormalizeBounds(...)` / `Clamp(...)` / `IsUsable(...)`: normalize to a 0–100% VBIOS window, never above the factory default, reject locked ranges where minimum >= default, and clamp the Cool 70% / Balanced 85% presets to the exact applied percentage.
- `IGpuPowerBackend`: `Bounds`, `TryReadPercent(out double, out string)`, `TryApplyPercent(double, out double, out string)`, `TryRestoreDefault(out string)`. Implementations: `NvapiPowerBackend` (loads `nvapi64.dll` only via `NativeLibrary.Load(..., DllImportSearchPath.System32)`; resolves `0x34206D86`, `0x70916171`, `0xAD95F5ED` through `nvapi_QueryInterface`), `AdlxPowerBackend` (loads `amdadlx64.dll` from System32; calls `IADLXSystem::GetGPUTuningServices`, `IsSupportedManualPowerTuning`, `GetManualPowerTuning`, then `GetPowerLimitRange` / `GetPowerLimit` / `SetPowerLimit` through the official C vtable ABI; converts ADLX signed offsets such as `-30..+10` to absolute percentages and back), and `AdlPowerBackend` (loads `atiadlxx.dll` from System32 and uses `ADL2_OverdriveN_CapabilitiesX2_Get`, `ADL2_OverdriveN_PowerLimit_Get`, `ADL2_OverdriveN_PowerLimit_Set`; manual mode 3, default mode 1). The AMD factory tries ADLX first, then ADL when the driver package does not expose ADLX.
- `SettingsWindow`: `OnGpuPowerStateChanged(...)`, `UpdateGpuPowerUi(...)`, `UpdateGpuPowerTelemetryUi()`, `ChkGpuPowerEnabled_Changed(...)`, `BtnGpuPowerCool_Click`, `BtnGpuPowerBalanced_Click`, `BtnGpuPowerFull_Click`, `BtnGpuPowerReset_Click`, `SldGpuPowerLimit_ValueChanged`, `GpuSliderApplyTimer_Tick`.
