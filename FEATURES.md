## Health, reporting, diagnostics, and accessibility

- **First-run and Post-update Health Check (`HealthCheckService`, `HealthCheckWindow`, `Tools > Health check`)**: Runs once after the first dashboard launch and after a successful update, plus manually from Tools. It reports administrator status, PawnIO, LibreHardwareMonitor CPU/GPU sensor availability, GPU backend/name, startup task, power plan, and update staging. Rows are ordered by severity, use text and a glyph rather than color alone, and every Warning/ActionRequired row offers an action such as installing PawnIO, enabling or removing the startup task, repairing update staging, opening Settings/System Information, opening the update log, or retrying. A standard-user session is informational. The dialog supports recheck, Escape, tab traversal, screen-reader names, and work-area clamping; closing it records `HasCompletedFirstRunHealthCheck` so the first-run prompt is one-shot.
- **Session Report and Chart Event Annotations (`SessionReportService`, `SessionReportWindow`, `Tools > Session report`)**: Builds a readable report from the existing telemetry ring buffer and activity log: session range, CPU/GPU/hotspot peaks and averages, time above configured temperature and hotspot-delta thresholds, cooling/profile changes, alert and fan-event counts, update history, and a latest-30 diagnostic timeline. The report can be copied as text, and temperatures follow the existing Celsius/Fahrenheit setting. The existing CPU and GPU charts draw markers for the same cooling/profile/alert transitions, and the chart tooltip names the nearest event, explaining temperature spikes. This is separate from raw CSV export and the support bundle and does not create a second telemetry store.
- **GPU Diagnostics and Thermal Headroom (`GpuDiagnosticsService`, `System Information`)**: Read-only rows show GPU name, driver version and date, vBIOS, PCI vendor/device/subsystem/revision and PNP ID, TDR count from the Windows System log, current/average/max hotspot-to-edge delta with a trend label, edge temperature, configured thermal limit, and remaining headroom. Data comes from WMI, the display-class registry, the System event log, and existing telemetry. Thermal values follow the existing unit setting. Fan, voltage, and power-limit writes remain out of scope; unavailable vBIOS values are labeled rather than guessed.
- **Accessibility Pass (dashboard, Settings, companion windows)**: Windows text scaling is now honored. `TextScaleService` reads the Windows `TextScaleFactor` and applies a matching layout transform and window size to the dashboard, Settings, health check, and session report, so fixed labels, combo columns, and timeline columns scale together rather than clipping. The Settings search popup, CPU core popup, and combo dropdowns are included; dropdown placement stays LTR so Arabic RTL does not push it off-screen. Keyboard traversal and visible focus cover Settings checkboxes, custom buttons, the CPU temperature control, and the new windows; Escape closes the CPU core popup and the health/report windows. Localized screen-reader names cover the Settings combos/actions/content, dashboard timeframe, and CPU temperature details. High contrast substitutes system colors for the hero, chart lines/backgrounds, focus borders, checked controls, accent action surfaces, and text, and accessibility changes reapply even under a saved Dark/Light theme. Arabic RTL layouts and English were checked at 150% high contrast with no clipped labels, timeline overlap, or off-screen dropdowns. Scales above 150%, real screen-reader speech, and a fresh light theme pass remain unverified.

## Opt-in power utilities

- **Windows Timer Resolution (Opt-In) (`Settings > Autopilot`, `TimerResolutionService`)**: Default Off. Modes are Off, Autopilot Only, and Always On, with 0.5 ms or 1.0 ms targets clamped to the hardware query. Battery guard defaults on and always releases the request on DC power, showing a Paused on battery badge. The status strip shows current and requested values. Windows 11's `GlobalTimerResolutionRequests` is detected read-only; enabling or reverting it requires an explicit confirmation and restart, and is never automatic.
- **Automatic Standby List Cleanup (Opt-In) (`Settings > Memory`, `StandbyPurgeService`)**: Default off, including the game sub-toggle. The card shows a read-only In Use / Standby / Free overview. When enabled, it checks every 5 seconds, requires Free RAM below 1024 MB and Standby above 4096 MB by default, waits at least 5 minutes between attempts, and skips Autopilot game sessions unless allowed. It purges only the standby list, never active working sets, and reports the last result and freed bytes. Thresholds and cooldown are configurable.
- **Keep Awake (`Settings > General`, System Tray, `KeepAwakeService`)**: Runtime-only and always starts off. Presets are 15/30/60/120 minutes, custom 1 minute-72 hours, and indefinite with a mandatory confirmation. The display-off preference defaults to checked. A live countdown and Stop action appear in Settings and the tray header; stop, expiry, and app exit clear the execution state. The active timer is deliberately not persisted.

## Performance, diagnostics, and release controls

- **Chart Decimation and Render Coalescing (`ChartSampleReducer`, `MainWindow`)**: CPU and GPU charts reduce each visible timeframe within a point budget near twice the plot width. Each bucket keeps its minimum, maximum, and original indices, and profile boundaries are reduced per segment so plan-colored runs stay intact. Hover still reads the full sample list, so tooltips keep exact values and timestamps. A 200 ms `DispatcherTimer` redraws only when a telemetry tick marked the charts dirty; load, resize, theme, timeframe, and settings changes still redraw immediately.
- **Local Activity Timeline and Support Bundle (`ActivityLogService`, `SupportBundleService`, `Settings > About`)**: The latest 50 events persist as JSONL at `%AppData%\CryoTray\activity.jsonl`; malformed lines are ignored, user paths are sanitized, and consecutive identical events within five minutes are collapsed. When the cap is reached, the file is rewritten with only the retained events, so old records are removed rather than merely hidden. The About tab has a **Recent activity** disclosure that starts collapsed and can be opened from its heading or chevron; it shows time, severity, and message for app, profile, alert, update, cleanup, RAM, and Game Mode events. **Save support bundle...** inside the disclosure writes a ZIP with a summary, existing diagnostics, system-info report, activity JSONL and readable text, allowlisted settings, and the updater log tail. The settings projection omits paths, hotkeys, aliases, app lists, and window positions.
- **Stable and Preview Update Channels (`AppSettings.UpdateChannel`, `UpdateService`, `Settings > About`)**: Stable uses `releases/latest`; Preview reads the latest 20 releases, skips drafts and malformed versions, and picks the highest base version with stable preferred on a tie. Cache and ETag are per channel and clear when the channel changes. Preview tags use `v<base>-preview.N`, and preview builds bump the numeric patch so the existing `IsNewer` comparison remains valid. The release workflow accepts a channel and preview number, publishes previews with `--prerelease`, and leaves the stable path unchanged.
- **Read-only Rollback Readiness (`RollbackReadinessService`)**: The compact **Verify rollback readiness** button checks the saved manifest, file hashes, protected ACLs, reparse safety, app location, and required `CryoTray.exe` and `CryoTray.dll` on a background thread, so hashing does not block the Settings window. The rollback actions are disabled while it runs and the status line shows a checking state. About reports file count, size, and the localized result, and the check is recorded in activity without consecutive duplicates. In Debug builds, or Release builds with the administrator-created developer marker, the location check follows the app's developer-launch rule and the result says restore requires a protected install location; Release installed copies still enforce it. It never writes to the app directory; the existing restore button remains the only write path and keeps its own update-time location guard.

## Telemetry & Hardware Monitoring

- **Adaptive Telemetry Polling (`TelemetryDemandTracker`, `TelemetryPollPolicy`, `HardwareMonitorService`)**: Reference-counted leases from open windows and services select 1 s for interactive or CSV demand, 2 s for tray/alerts/memory only, and 3 s when idle. A hidden or minimized dashboard releases its lease while the tray baseline keeps 2 s. CPU and GPU always update; fans/controllers are read only when a visible surface needs them; storage is cached and refreshed every 10 s active or 30 s background. Win32 `GlobalMemoryStatusEx` provides RAM totals and PDH provides `% Processor Performance`. Uses `double.NaN` / `null` when sensors are unavailable rather than synthetic fallbacks.
- **Runtime PawnIO Driver Check & Recovery**: Checks `HKLM\SYSTEM\CurrentControlSet\Services\PawnIO`, shows actionable install/download banners in `MainWindow` and `SettingsWindow` when missing, and automatically reopens LHM once PawnIO is installed.
- **Primary GPU Selection & Per-GPU Telemetry History (`Settings > GPU`, `TelemetrySample`, `TelemetryRingBuffer`, `MainWindow`)**: Isolates telemetry per GPU, prioritizes GPU Core / D3D 3D load sensors, collects GPU core clock MHz and VRAM used/total MB into snapshots and diagnostics, defaults to Auto (discrete GPU priority), lets users pick any detected GPU via `PreferredGpuIdentifier`, and keys ring-buffer GPU temperature history per GPU identifier so switching GPUs never mixes chart or stats history.
- **60-Minute Ring Buffer, Charts & Expanded CSV Export (`TelemetryRingBuffer`, `TelemetryCsvService`)**: Stores up to 3,600 telemetry samples in memory (60 minutes at 1 s); powers CPU and per-GPU charts across 1, 5, 10, 30, and 60 minute timeframes with hover tooltips, unavailable-sensor states, ring-buffer CSV export (including `GpuHotspotC,GpuVramTempC,GpuFanRpm`), and live 1 Hz CSV logging from the `Tools` menu with clean stop/error reporting on write failure.
- **Storage Telemetry, SMART Health & Per-Drive Filtering**: Validates drive temperature range `(0, 150) °C`, displays drive temperature, SMART percentage health (`Good` / `Fair` / `Worn` / `Replace`), and model tooltip on the dashboard, with per-drive checkboxes (`Settings > Disk`, `ExcludedDrives`) to hide cold/external drives from the dashboard and disk temperature alerts.
- **Per-Core CPU Breakdown**: Maps direct Intel core diodes or weighted AMD CCD/Tctl temperatures into `CPU00..` cells in the hero hover bubble, underlining cores tied for hottest and showing package wattage.
- **GPU Detail Expansion (`Settings > GPU`, `MainWindow`)**: An optional details row under the GPU health row shows VRAM used/total, core and memory clocks, and a compact reported performance-limit reason. `ShowGpuDetails` is off by default; enabling it adds the row and adjusts the dashboard height. Values come from LibreHardwareMonitor `SmallData`, `Clock`, and `Factor` sensors and render `--` when the hardware does not expose them.
- **Read-only Motherboard Fan Speeds (`HardwareMonitorService`, `SystemInfoWindow`)**: Collects raw `SensorType.Fan` readings (including 0 RPM headers) from motherboard, controller, and their subhardware into `HardwareSnapshot.Fans`, lists only moving fans in System Information, and renders `--` when the driver reports none. `Settings > View > System information` toggles the row (`ShowFanSpeeds`, on by default).
- **Live Fan Health Panel (`FanHealthService`, `SystemInfoWindow`)**: Adds a read-only Fan health disclosure under Fan speeds, collapsed by default and opened by clicking the heading or its `>` chevron. It lists each motherboard header and the primary GPU fan, current RPM, state (`Watching`, `Armed`, `Idle at 0 RPM`, `Stopped`), arming or alert countdown, last alert time, and a **Test fan notification** button. **Hide idle fans** is on by default and filters `Idle at 0 RPM` rows while always keeping `Stopped` rows visible; unchecking it shows every header. Fan alerts open System Information, expand the panel, and highlight the affected fan.
- **Friendly Fan Names (`AppSettings.FanAliases`)**: `Settings > General > Fan names` maps each motherboard header and the GPU fan to an optional custom label. Aliases are saved in settings and applied consistently in the Fan health panel, moving fan-speed rows, fan notifications, and diagnostics; blank names fall back to the sensor label.
- **Fan Speed Diagnostics Filter (`SystemInfoWindow`)**: The Fan health disclosure keeps a local Hide idle state, preserves highlighted deep-link rows even when idle, and shows a localized empty-state message when every remaining fan is idle.
- **GPU Fan Health (`FanHealthService`)**: Feeds `HardwareSnapshot.GpuFanRpm` through the same arming and stop timer, using GPU load and GPU temperature for demand so idle zero-fan mode stays quiet. A single GPU RPM sensor is treated as one fan signal.
- **Storage Health Watch (`StorageHealthAlertService`)**: Optional notifications when a non-excluded drive enters `Worn` or `Replace`, or its SMART health drops by 10 points (including cumulative gradual wear tracked against a session baseline watermark), with a 10 minute cooldown and a **Settings > Disk** toggle (`StorageHealthAlertsEnabled`, on by default).
- **Tray Badge Metric Selector (`TrayIconManager`, `Settings > View`)**: Independent CPU and GPU badge values for temperature, load, or RAM percentage, using the existing digit palettes and renderer. Temperature remains the default.
- **Top Process Consumers (`ProcessUsageService`, `SystemInfoWindow`)**: A collapsed **Top processes** disclosure in System Information lists the six processes driving CPU or GPU load, with CPU %, GPU %, and working-set memory. CPU uses `TotalProcessorTime` deltas; GPU sums WMI `GPUEngine` `engtype_3D` utilization by PID. Sampling runs every 2 seconds only while the section is open, and the panel reports when GPU process counters are unavailable.

## Cooling Mode & Power Management

- **Six-Profile Power Engine (`PowerProfile`, `PowerPlanService`)**: Six deterministic GUIDs: Cooling (`c7a00001`), Legacy (`c7a00006`), and Gaming Low/Medium/High/Ultimate (`c7a00002`-`c7a00005`). Each profile has explicit AC/DC values for processor, PCIe, USB, disk/NVMe, and personality settings. Switching duplicates Balanced into the target GUID, writes the values, activates the target, then deletes only the other CryoTray whitelist GUIDs plus the obsolete `CryoTray Cooling` name. It never deletes built-in or third-party plans. External power-plan changes are synced every 2 seconds, and `/uninstall-cleanup` removes every CryoTray scheme.
- **Original Plan Capture & Restore**: `OriginalActivePowerPlanGuid` records the first non-CryoTray active plan. Exit with `DisableCoolingModeOnExit` and uninstall restore it. The old single `CryoTray Cooling` plan is migrated to Legacy when active at startup.
- **Battery Auto-Cooling Rule**: Optional `EnableCoolingOnBattery` (`Settings > General`) via `SystemEvents.PowerModeChanged` enables the preferred cooling profile on battery and restores the preferred off profile on AC reconnect only when battery activated it.
- **Preferred Profile Selectors**: Settings > CPU offers `CryoTray — Cooling` / `CryoTray Cooling - Legacy` for Cooling Mode on, and Windows Balanced (default), Gaming Low/Medium/High/Ultimate for Cooling Mode off. Each item shows a colored dot and a live English/Arabic explanation. The tray context menu adds a **Power Profile** submenu with a checkmark on the active plan.
- **Dashboard Profile Dropdown**: The active-plan label under Cooling Mode is a compact dropdown grouped into **Cooling** and **Cooling Off**. It uses the System Information table language: a bare accent checkmark with no checkbox square, a profile accent dot, a semibold name, a right-aligned muted badge, and alternating dark row bands. Checkmarks mirror both preferred profiles from Settings; choosing a profile saves it and applies immediately when that mode is active, otherwise it updates the future preference. Settings and the dropdown stay synchronized in both directions; row descriptions are exposed as accessible help text rather than hover tooltips.
- **Configurable Legacy CPU Cooling Controls**: Adjusts `PERFBOOSTMODE` (Disabled/Enabled) and `PROCTHROTTLEMAX` (50% to 100%) on the Legacy profile only.
- **Profile-Matched Visuals**: Cooling and Legacy preserve the exact ice-blue ON palette, Gaming High and Windows Balanced preserve the exact copper OFF palette, Gaming Low is emerald, Gaming Medium is amber, and Gaming Ultimate is crimson. The CPU banner, outer frame, fan icon, toggle, and selector dots follow the active profile, with the banner animating over 400 ms. The CPU chart preserves each sample's plan color: Cooling and Legacy blue, Balanced and High copper, Low emerald, Medium amber, and Ultimate crimson. A plan change only colors new samples, so older runs keep the color they were recorded with.
- **Windows Balanced Off Profile**: `PowerProfiles.BalancedProfile` maps to the built-in Balanced GUID and is the default off profile. Selecting it activates Windows Balanced and removes every installed CryoTray profile, so the app can run with zero CryoTray plans in Power Options.
- **Custom Global Hotkey Recorder (`GlobalHotkeyService`)**: Interactive shortcut recorder in `Settings > General` supporting `Ctrl`, `Alt`, `Shift`, and `Win` plus `A-Z`, `0-9`, or `F1-F12` via message-only `HwndSource`, with conflict detection feedback.
- **Safe Exit Behavior (`ConfirmExitWindow`)**: Optional `DisableCoolingModeOnExit` prompt that restores the captured original Windows power plan when exiting, including while a gaming profile is active.
- **Opt-In GPU Power Limit Control (`GpuPowerControlService`, `NvapiPowerBackend`, `AdlxPowerBackend`, `AdlPowerBackend`, `Settings > GPU`)**: Disabled by default. Enabling starts at the GPU's native VBIOS default (never automatically at 70% or 85%), then exposes Cool (70%), Balanced (85%), Full / Default (100%), a persistent Reset, and a fine slider bounded by the VBIOS minimum and the factory default capped at 100%. Presets clamp to the live VBIOS bounds, writes are serialized on a background thread, read back, and the default is restored on toggle-off, normal exit, unhandled exceptions, and `SystemEvents.SessionEnding`. Unsupported or locked firmware shows the exact badge "Power limit control not supported by this GPU's VBIOS" and leaves the toggle disabled. `GpuPowerControlEnabled` defaults false; the optional startup re-apply checkbox defaults false. NVIDIA uses `nvapi64.dll` only from System32; AMD uses ADLX manual power tuning (official C vtable ABI, no native shim; signed ADLX offsets are converted to absolute 70–100% values) and falls back to the ADL2 OverdriveN surface for older driver packages. No second telemetry poll is created.
- **Smart Download-Completion Timer (`DownloadTimerService`, `DownloadTimerEngine`, `Settings > Autopilot`, tray menu)**: Disabled/armed-off by default. Samples non-loopback, non-tunnel network adapters every second, waits for an active download when configured, then requires a continuously quiet window (default 5 minutes below 200 KB/s) and a disk guard below 2 MB/s before starting a topmost 60-second warning with a large Cancel action. Sleep is the default action; Hibernate and Shut Down are selectable. The timer auto-disarms and persists false after firing or manual cancellation, so waking the PC cannot immediately put it back to sleep. Disk-counter failure fails closed rather than interrupting unpacking.

## Autopilot & Alerts

- **Game Mode and Toolhelp32 Process Scan (`AutopilotService`, `AutopilotAppProfiles`)**: Scans running processes every 2.5 seconds via `CreateToolhelp32Snapshot`, then resolves a foreground or any-running app rule, otherwise an optional fullscreen Direct3D/presentation/borderless game detected through `SHQueryUserNotificationState`. Each whitelisted process maps to a profile; old entries fall back to `PreferredGamingProfile`. The service captures the previous profile once, switches only when the resolved target changes, and restores the captured profile when the rule clears. It respects manual profile changes while a rule is active and does not resume Cooling Mode when a timed pause is still in force. Optional `AutopilotForegroundOnly` restricts the whitelist branch to the current `GetForegroundWindow` process (`Settings > Autopilot`, off by default).
- **Temperature Alerts (`TemperatureAlertService`)**: Thread-safe per-component thresholds for CPU, GPU, GPU hotspot, GPU VRAM (hotspot/VRAM use `Math.Max(HighTempThresholdGpu + 15, 95)` °C), and non-excluded disks, with 10 minute cooldown, 3 °C re-arm hysteresis, mute toggle that clears stale state, bilingual alerts, and a test notification button.
- **GPU Hotspot-to-Edge Delta Watch (`TemperatureAlertService`, `Settings > General`)**: Optional warning when the primary GPU's hotspot stays at least a configurable gap (default 25 °C, range 15–40 °C) above its edge temperature for 5 minutes. A sustained large gap can indicate dried thermal paste or a mounting problem. A dip below the threshold restarts the 5 minute window, and after one alert the watch enforces a 30 minute cooldown. `GpuDeltaAlertsEnabled` is on by default; the threshold follows the selected temperature unit in the label and notification.
- **Fan Health Watch (`FanHealthService`)**: Arms each fan header only after 60 seconds continuously above 300 RPM, then raises a tray warning if it reads 0 RPM for 30 seconds while CPU or GPU load is at least 25% and its temperature is at least 60 °C. Headers that never spin are ignored, demand must persist for 15 seconds, suspend/resume clears state with a 60 second grace period, and each fan has a 10 minute cooldown. `Settings > General` toggle (`FanHealthAlertsEnabled`, on by default).

## Storage & Cache Cleanup

- **Grouped RAM scope dropdown (`MainWindow`)**: The chevron beside Optimize RAM opens a profile-selector-style menu with a muted `Cleanup scope` header, bare accent checkmarks, RAM accent dots, compact action titles, and right-aligned `Working sets` / `Standby list` descriptors. A divider leads to the `Storage & Cache Cleanup...` utility row. The popup keeps keyboard menu navigation, RTL layout, saved scope checks, and full help text for the technical action descriptions.
- **RAM dropdown entry (`MainWindow`, `StorageCleanupWindow`)**: The button beside Optimize RAM has a separator and a **Storage & Cache Cleanup...** action. It opens a 392 x 630 modeless companion beside the dashboard, reuses that window instead of opening duplicates, and closes from Close, Escape, or the titlebar when idle. The panel scans four categories asynchronously, then shows selected bytes and files found, `Selected X of Y` with a selection-aware category distribution bar, a system-drive free/total bar, per-row sizes and file counts, plain-language descriptions, and Recommended / Optional / Gamers / Advanced badges. The primary action is `Clean {selected bytes}` and stays disabled until a scan succeeds and at least one category is selected; opt-in categories require an inline confirmation. Scan/cleanup progress, cancellation, error feedback with Rescan, and a per-category freed-byte result are shown in the panel. Unit tests cover the opt-in confirmation matrix, active-cancel window retention, and the close-during-work prompt. During progress, the phase text and indeterminate bar replace the redundant chart-strip label.
- **Conservative targets and honest accounting (`StorageCleanupService`)**: User and Windows Temp contents, opt-in browser cache directories only (Chrome, Edge, Brave, Opera/Opera GX, Firefox), opt-in GPU shader caches (DirectX, NVIDIA, AMD, Intel), and opt-in Windows Prefetch `.pf` / `.db` files. Browser cookies, passwords, logins, history, bookmarks, sessions, local storage, and IndexedDB are never touched. Reparse points are skipped, every path is containment-checked, locked files are counted separately, and bytes are reported only after a successful delete.
- **Broad-root guard (`StorageCleanupService`)**: Drive roots, Windows and System32/SysWOW64, user profiles and their direct child folders, `C:\Users`, LocalAppData, AppData, ProgramData, Program Files, and other broad user or system folders are refused before traversal. The guard also covers redirected TEMP paths and the internal sandbox seam, while keeping `%WINDIR%\Temp`, `%WINDIR%\Prefetch`, browser caches, and GPU caches allowed.
- **Persistent preferences and browser hint (`AppSettings`)**: Temp is checked by default; browser cache, GPU shader cache, and Prefetch are unchecked. Checkbox changes persist to JSON. A subtle note appears when Browser Cache is checked while a supported browser is running, explaining that active files will be skipped safely. A completion banner reports freed bytes, deleted files, and skipped active files, then refreshes row sizes.

## System Tray & Companion Windows

- **Dynamic Tray Badges & Second-Launch Activation (`TrayIconManager`, `App`)**: Separate GPU (green) and CPU (coral/cyan) badges or one combined split badge showing temperature or `--`, with GPU registered first so a fresh tray places GPU on the left and CPU on the right. The owner-drawn dark `#1E1E1E` tray context menu + pause submenu (`#2D2D2D` hover pill, trailing `#29B6F6` checkbox, vector chevron, and Arabic RTL flip) supports checkable `Overlay Click-Through`, and named `EventWaitHandle` activation so relaunching `CryoTray.exe` focuses the existing dashboard.
- **Optional Memory Tray Badge (`Settings > Memory`, `TrayIconManager`)**: Off by default. Enabling shows a third badge with the current RAM usage percentage, black or white digits, and a user-picked badge color with reset. White digits use a darker derived shade and dark picks are lightened for at least 4.5:1 contrast. The badge stays independent of the CPU/GPU merge option and has its own localized tooltip.
- **Dashboard (`MainWindow`)**: Tray-anchored or freely positioned dark window (`444 x 673` baseline) with animated six-petal vector cooling fan, keyboard-accessible `BtnCoolingToggle` and `BtnCpuTempCores`, CPU/GPU charts with a selectable GPU metric, optional GPU details row, RAM row, filtered SSD rows, dark owner-styled `ToolsContextMenu` CSV export/logging and About tab actions (zero white icon gutter), and optional Overlay/Autopilot rows.
- **Floating Telemetry Overlay (`OverlayWindow`)**: Always-on-top draggable pill with configurable opacity (0% to 100%), optional click-through `WS_EX_TRANSPARENT` pass-through (`OverlayClickThrough`), and selectable CPU, GPU, RAM, and battery metrics. Battery shows percentage plus `Charging`, `Full`, `Plugged in`, or `On battery`; it is omitted on desktops without a battery. The same status is appended to the CPU/GPU tray tooltip, with safe length clipping.
- **CPU Temperature Test (`StressTestWindow`)**: Multi-core CPU stress generator running on `BelowNormal` background worker threads with live temperature/clock readouts, 60-sample chart, inline Cooling Mode switch, and session CSV export (`Export CSV`).
- **System Information (`SystemInfoWindow`)**: On-demand WMI, EDID monitor, active NIC, Event 100 boot duration, BSOD count, drive matching (serial, disk index, model), Cooling-Mode-scoped CPU temp stats, a collapsed **Top processes** panel with CPU/GPU/memory by process, plain-text report export, and **Copy diagnostics** for a short support snapshot with app version, CPU, GPU, temperatures, RAM, fan states, and drive health. Copied diagnostics exclude serial numbers, PC names, and file paths.

## Settings, Localization, Updates & Installer

- **Developer Launch (`App.xaml.cs`, `UpdateStorage.IsDeveloperModeEnabled`)**: Debug builds skip the installed-copy location guard so the app can run from `bin\Debug\net8.0-windows` during IDE work. Release builds skip it only when an administrator has created `%ProgramData%\CryoTray\dev-mode`; the marker is checked after the protected data root is secured, and update installation still refuses a user-writable app folder. README and CONTRIBUTING document both paths.
- **Release Status (2026-11-19)**: `v0.0.103` is the public latest release, built from `aa2d167` by run `44629021389`, with setup, portable ZIP, update archive, and SHA-256 assets. It adds the rollback save toggle, rollback delete control, download cache actions, rollback date/size display, and the administrator-only developer marker. The `v0.0.102` prerelease was deleted after `v0.0.103` shipped. The old `v0.0.100` in-app upgrade test failed because that client prefers a ZIP asset and hit `Access is denied`; the published setup migrated that test machine and is the required one-time path for `v0.0.100` users. The live audit found no defect in the successful `0.0.101` to `0.0.102` path; a complete rollback backup exists, while rollback and failure recovery were not exercised live.
- **Settings Persistence & Portability (`SettingsService`)**: Stores JSON settings in `%APPDATA%\CryoTray\settings.json` with Export, Import, Reset, and Task Scheduler startup entry (`StartupTaskService`).
- **Settings Tab Grouping and Search (`SettingsWindow`, `SettingsSearchMatcher`)**: Nine tabs. View keeps theme, tray badge controls, frame colors, docking, RAM/Autopilot rows, and the motherboard fan-speed readout. Memory owns cleaning and auto rules, the RAM hotkey, and the opt-in memory tray badge. Overlay owns Show Overlay row, click-through, opacity, CPU/GPU/RAM readouts, and battery percentage. CPU owns CPU power usage, clock/base speed, graph, profiles, cooling controls, and alert threshold. GPU owns primary GPU, alert threshold, dashboard GPU readouts, GPU details, graph metric, and the opt-in power limit. The 300 px header search has an integrated magnifier, clear action, Ctrl+F focus shortcut, match count, section icons and labels, highlighted matches, a slim scrollbar for the results and body, an empty state with guidance, and a keyboard footer. It indexes localized labels from every tab once, excludes user-generated lists, requires every query token, ranks exact titles and title prefixes above title-word and keyword matches, and jumps to the matching tab and control. The popup opens once at its measured full content height; it does not briefly show a summary-only frame or reopen after layout. Up/Down selects, Enter opens, and Esc clears then closes through `PreviewKeyDown`, so the TextBox cannot swallow the arrows. The popup window stays LTR while its rows and footer mirror the UI language, preventing mirrored Latin text; the field intentionally has no tooltip because WPF showed the Ctrl+F hint on keyboard focus and it covered the tab strip and results. Match highlights use `SearchMatchBrush` and section labels use `TextTertiaryBrush` for AA contrast in both themes. Both locales have complete search strings.
- **Notification Master Switch & Fan Names Disclosure (`AppSettings.DisableAllNotifications`, `SettingsWindow`)**: General starts with a Notifications group whose **Disable all notifications** switch suppresses every tray balloon, including temperature, fan, storage, update, RAM, and test notifications. Update notices are not marked as sent while it is on. Fan names moved to the end of General as a collapsed disclosure with a keyboard-accessible chevron.
- **Bilingual UI & RTL (`LocalizationService`)**: Full English (`Strings.en.xaml`) and Arabic (`Strings.ar.xaml`) resource dictionaries with dynamic RTL layout switching while keeping numeric metrics LTR.
- **Dark / Light / System Appearance (`ThemeService`, `Settings > View`)**: A `Theme` dropdown at the top of the View tab offers **Dark** (default), **Light**, and **System**, matching the language selector. `System` reads the Windows `AppsUseLightTheme` preference and follows live `UserPreferenceChanged` events. Shared theme resources repaint every companion window, dashboard surface, chart, popup, context menu, and owner-drawn tray menu; the user-defined cooling frame color remains independent.
- **Resilient & Protected GitHub Updater (`UpdateService`, `UpdateStorage`, `UpdateBackupService`, `UpdateCompletionService`, `UpdateStatusService`)**: Checks run every 5 minutes while the dashboard is visible and every 30 minutes in the tray, plus startup, resume, and network reconnect. The dashboard strip offers Update, About, 24-hour Later, and persistent Skip; About shows release notes, last checked time, result, download speed/ETA, and Cancel. Downloads use stable locked work directories, retry transient errors, resume with Range, enforce size/free-space limits, and use conditional GitHub requests. Staging and rollback live under `%ProgramData%` with an Administrators owner, protected Administrators/SYSTEM ACL, recursive reparse rejection, and untrusted-content clearing. The helper verifies manifest version, every file SHA-256, and delete paths before copying, deletes stale files, restores the verified backup on failure, and writes the one-time success marker only after completion. Creating the next rollback backup rotates the rollback root and removes the previous version; successful updates and rollback launches do not delete the current backup. About also provides a **Save rollback on update** checkbox (enabled by default; off skips `CreateBackup()` and automatic failure restore), a compact **Delete backup** action with confirmation, and a **Clear downloads** action with cache-size display when downloaded update files exist. Rollback status includes the backup creation date and size. `DeleteCurrent()` removes the current rollback directory and manifest while preserving settings and the installed app; `ClearDownloadCache()` removes only the downloaded update files. Last-check state persists across restarts; a persisted **Available** shows **Check again** until the release object is fetched again. Installed copies are identified by a matching Inno uninstall key or an Inno `unins000.exe` marker under Program Files; portable copies remain portable in Program Files and use `CryoTray-Update-*.zip` from an administrator-protected folder. Authenticode is best-effort, not required. The app exits with a localized error when its folder is writable by standard users; otherwise the app folder and its files are secured to Administrators/SYSTEM full control and Builtin Users read/execute before startup work continues.
- Rollback reads are secured before use: startup initializes the ProgramData update and rollback roots, `GetCurrent()` and `LaunchRollback()` enforce the rollback guard, and a pre-created untrusted manifest is cleared and rejected by the regression test. The installer also removes a previously registered custom Inno installation after a successful Program Files install when the path passes strict safety checks.
- **CI Installer & CLI Diagnostics**: `.github/workflows/release.yml` runs the `/test` verification suite before publishing `CryoTray-Setup-<version>.exe` (Inno Setup + bundled `PawnIO_setup.exe` + `/uninstall-cleanup`), the portable zip, and the updater archive `CryoTray-Update-<version>-win-x64.zip` with versioned per-file hashes and a cumulative delete list built from the previous manifest's `files` and `delete` history; a missing previous baseline fails packaging. `/dump` writes `cpu-sensors.txt` via `CpuSensorDump`.
- **Local Installer & Portable Build (`build-installer.ps1`, `Installer/CryoTray.iss`)**: Validates the three-part `VERSION`, verifies the bundled PawnIO installer, publishes self-contained win-x64 without PDBs, locates or installs Inno Setup 6, writes `Installer\Output\CryoTray-Setup-<version>.exe`, and creates `release\CryoTray-<version>-win-x64.zip` with `PawnIO_setup.exe` at the archive root. The Inno script requires x64 and admin, forces the default Program Files directory, does not reuse a previous custom path, reads the previous HKLM uninstall `InstallLocation`, removes a registered old CryoTray folder after a successful install only when it passes strict path checks, sets an Administrators owner and Administrators/SYSTEM full-control plus Users read/execute ACL, clears a stale success marker on manual install (unless `/PRESERVEUPDATE`), removes the startup task, runs `/uninstall-cleanup`, restores Balanced as a fallback, and silently installs PawnIO only when absent.
- **GitHub Release Automation (`.github/workflows/release.yml`)**: Supports both `VERSION`-change pushes and manual `workflow_dispatch`. Builds and runs the suite, publishes self-contained win-x64, signs the app before compiling Inno Setup, signs the setup afterward, packages the portable zip with PawnIO, writes the hashed update manifest and SHA-256 files, and skips versions whose tag already exists. v0.0.101 remains the public latest release; v0.0.102 is a prerelease test build. Both use unsigned assets because signing secrets are not configured.
